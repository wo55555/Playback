# 录制快捷键与状态层开发文档

## 需求

### 目标

为普通游戏世界的回放录制提供无需打开命令输入框的快捷控制，并在录制期间向玩家显示简洁的录制状态。玩家可在设置界面修改两个快捷键及状态层位置。

### 功能范围

- 默认按键：`P` 开始或结束录制，`L` 暂停或继续录制。
- `P` 的状态转换为：空闲时开始录制；录制中或暂停时结束录制。
- `L` 仅在录制活动期间生效：录制中切换到暂停，暂停中切换到继续；空闲状态不执行操作。
- 录制状态层仅在普通游戏世界、游戏 HUD 可见且录制活动时显示。
- 状态层没有背景卡片、边框或填充，仅显示红色圆点、状态文案和录制时长，例如 `● 录制中 3:25`。
- 暂停时显示 `● 已暂停 3:25`；时长为累计有效录制时长，不计暂停时段。
- 玩家可将状态层放在左上、右上、左下、右下四个位置；默认左上。
- 设置页面提供开始/结束、暂停/继续两个按键绑定控件，状态层显示开关和位置选择；默认设置必须可恢复。
- 按键绑定应拒绝空按键、保留键和已被另一个录制动作占用的按键，并显示可理解的冲突提示。

### 非目标

- 不改变现有 `/record start`、`/record pause`、`/record stop` 命令的语义。
- 不在回放世界、主菜单、加载页面或任意游戏菜单上接收录制快捷键或显示状态层。
- 本期不提供组合键、多个按键序列、状态层拖拽定位或录制完成通知。

## 架构

### 模块划分

| 模块 | 职责 | 主要依赖 |
| --- | --- | --- |
| `RecordingShortcutConfig` | 保存默认值、当前绑定、状态层开关和位置；负责校验与序列化 | 模组配置加载/保存机制 |
| `RecordingShortcutController` | 在游戏输入事件中将按键边沿转换为录制控制意图，并屏蔽非游戏场景 | `Recorder`、`Playback`、配置 |
| `RecordingStatusModel` | 维护录制起始时间、暂停累计时长和对 UI 只读的状态快照 | `Recorder` 状态变化 |
| `RecordingStatusOverlay` | 在现有 D3D12/ImGui 渲染路径中按配置绘制无卡片文字状态 | 状态模型、HUD 可见性、渲染器 |
| `RecordingSettingsPanel` | 编辑本地配置、捕获下一个按键、校验冲突、保存或恢复默认值 | 配置、输入捕获、状态层预览 |

### 复用边界

录制业务逻辑保持在现有 `Recorder` 中。该类已经定义 `Idle`、`Recording`、`Paused`、`Closing` 状态，并暴露 `start()`、`pause()`、`stop()`、`isActive()`、`isPaused()`；快捷键控制器不复制状态机，只根据这些接口决定调用哪个操作。

当前客户端更新钩子已经计算 HUD 是否可见，并调用 `tickReplayUI(hudVisible)`。状态层应复用此可见性判定，避免在菜单、加载页面和回放清理过程中显示。录制快捷键使用独立于编辑器 `KeyMap` 的运行时输入路径：编辑器按键表只服务编辑界面，且其 `matches()` 当前不验证修饰键，不能作为游戏全局快捷键的配置中心。

### 数据流

1. 模组加载时读取录制快捷键配置；缺失字段采用 `P`、`L`、启用状态层、左上角等默认值。
2. 游戏输入钩子接收按键按下边沿，先检查当前处于普通游戏世界、没有菜单/文本输入焦点且 HUD 有效，再将按键与配置映射比较。
3. 开始/结束动作读取 `Recorder` 状态并调用 `start()` 或 `stop()`；暂停/继续动作仅在 `isActive()` 时调用 `pause()`。
4. `Recorder` 的状态切换通知状态模型：开始时建立计时基准；暂停时累加本次有效录制时段；继续时重置运行基准；结束时冻结快照并隐藏状态层。
5. 每帧渲染读取状态快照和 HUD 可见性，计算四角锚点，输出红点、文案与格式化时间；不创建背景绘制命令。
6. 设置页面将编辑结果先保存在草稿中；保存时执行校验、落盘并让控制器和状态层读取新配置。恢复默认值仅重置草稿，点击保存后生效。

### 关键接口

建议给 `Recorder` 增加只读状态枚举或快照方法，以避免控制层通过两个布尔接口推断细节：

```cpp
enum class RecordingState { Idle, Recording, Paused, Closing };

struct RecordingStatusSnapshot {
    RecordingState state;
    std::chrono::seconds elapsed;
};
```

`RecordingShortcutController::onKeyDown(WPARAM key)` 只处理按下边沿并返回是否消费事件。`RecordingStatusOverlay::render(RecordingStatusSnapshot const&, HudBounds const&)` 只负责显示，不触发录制状态变化。设置页面通过 `RecordingShortcutConfig::validate()` 获取字段级错误。

### 异常处理

- `start()`、`pause()`、`stop()` 无法完成状态转换时，控制器不更新本地显示状态，并写入现有模组日志。
- 配置解析失败时保留默认值，并记录一次错误；不会阻止模组加载。
- 绑定冲突或无效键不写入配置，设置页面保留草稿并显示原因。
- 渲染器不可用时，录制快捷键与文件保存仍可正常工作；仅跳过状态层并记录一次降级日志。

## 执行

### 实施步骤

1. 扩展 `Config`，加入版本化的录制快捷键和状态层配置，并接入现有模组配置的读取、保存与默认值迁移。
2. 为 `Recorder` 提供可供 UI 消费的状态和累计有效时长快照；在开始、暂停、继续、停止、失败和退出世界时保持其一致。
3. 新建运行时快捷键控制器与输入钩子，在普通游戏 HUD 场景处理 `P`、`L`，并确保同一次按键不会在持续按住时重复触发。
4. 在当前 ImGui/D3D12 渲染流程中增加状态层渲染，使用四角锚点、文字阴影和红色圆点，严格不绘制背景卡片。
5. 在现有设置入口增加“录制”页面，包含两个键位捕获控件、状态层开关、位置下拉框、恢复默认和保存操作。
6. 补齐中英文文案：录制中、已暂停、开始/结束录制、暂停/继续录制、按键冲突和无效按键。
7. 编译后在普通游戏世界、回放世界、菜单、加载页和退出世界流程中进行手动验证。

### 验收标准

- 初始配置下，`P` 可从空闲开始录制，再次按下可结束并保存；`L` 可以暂停和继续。
- 连续按住按键只触发一次状态变化，释放后再次按下才可触发下一次。
- 状态层在录制与暂停期间显示在左上角，只有红点、文字和时长，没有矩形背景。
- 暂停期间时长静止，继续后累计；结束、失败、离开世界、打开菜单或进入回放世界时不显示。
- 更改键位和位置并保存后立即生效；重启后仍保留；恢复默认后回到 `P`、`L` 和左上角。
- 冲突键、空按键和不可用按键无法保存，且玩家可理解失败原因。
- 现有录制命令和回放编辑器快捷键回归正常。

### 验证方式

- 构建：使用仓库既有 `xmake` 构建流程，确保新增模块及平台头文件链接正常。
- 单元测试：对配置序列化/迁移、按键冲突校验、状态层文案和累计时长计算执行独立测试。
- 集成测试：以输入钩子驱动录制状态机，验证场景过滤、去抖、快捷键映射与世界退出清理。
- 手动测试：在 Minecraft 普通世界中录制至少一次，检查状态层视觉、四角位置、暂停计时与回放文件完整性。
