# 回复菜单动画与滚轮修正设计

## 需求

- 所有回复菜单 UI 动画统一严格控制在 `0.2s` 内完成，不使用会产生拖尾的指数追赶插值。
- 修复概况模式和详细模式中滚轮无法正常交互的问题。
- 详细模式列表内容和详情内容应由明确的滚动子区域接收滚轮输入。
- 概况模式卡片数量超过可视区域时支持垂直滚动。
- 不改变回放数据、选择、多选、双击打开、右键菜单和文件操作逻辑。

## 架构

- 动画仍由 `SelectReplayScreen` 私有状态维护，使用 `ImGui::GetIO().DeltaTime` 推进。
- `animate()` 改为按目标方向线性推进，并在达到目标时钳制到 `0` 或 `1`，保证单向动画最长为 `0.2s`。
- 视图切换继续使用已有 `mViewTransition`，仅统一其时间推进规则。
- 滚动区域属于 UI 布局层：概况网格、详细列表和详细内容分别拥有明确的滚动 child。
- 外层布局容器不再使用 `NoScrollWithMouse` 阻断子区域的滚轮事件；滚动条可按现有视觉设计隐藏，但滚轮接收权交给内部区域。

## 执行

1. 修改 `animate()`，移除指数插值，使用基于 `DeltaTime / 0.2s` 的严格线性插值。
2. 保持视图切换进度钳制在 `[0, 1]`，确保淡入完成时间统一为 `0.2s`。
3. 为概况卡片内容增加独立垂直滚动 child，并保持现有卡片列布局。
4. 移除详细列表外层和详情面板对滚轮的阻断标志。
5. 为详细列表滚动内容和详情内容明确配置垂直滚动能力。
6. 执行 `git diff --check` 和 Playback Release 构建。

## 验收

- 卡片 hover、选中、按钮和视图切换动画从开始到目标状态不超过 `0.2s`。
- 概况模式可使用鼠标滚轮浏览超出窗口的卡片。
- 详细模式可使用鼠标滚轮浏览左侧列表和右侧详情内容。
- 不出现滚轮被父容器吞掉、列表无法滚动或业务点击行为回归。
